# 배포 지도: GB10에 무엇이, RTX 3090에 무엇이 올라가는가

그림은 `docs/18-deployment-map.svg`다. 이 문서는 그림이 그리는 두 배치를 설명한다.

## 두 구성에 공통인 배치

| 구성요소 | 장치 | 이유 |
|---|---|---|
| 타깃 가중치(헬퍼 측) | GB10, 62.8 GB 상주 | 본체가 24 GiB에 들어가지 않고, GB10은 통합 메모리 121.7 GiB를 가진다 |
| PLE n-gram 테이블 | GB10, USB에서 51 GiB mmap | 읽기 위주이며 가중치 밖에 있다 |
| KV 캐시 | RTX 3090, 14 GiB | 엔진이 device 0에 KV를 예약하고, device 0은 3090이다 |
| 드래프트 MTP 가중치 | RTX 3090 | 드래프트가 타깃 owner 단계와 같은 장치에서 돈다 |
| 핫 전문가 캐시 | RTX 3090, owner 예산 4 GiB | 뜨거운 라우티드 전문가를 디코딩 단계 가까이에 둔다 |

링크는 PCIe Gen4 x4 non-P2P라서 장치를 넘는 활성화는 모두 호스트 메모리를 거친다.
그래서 타깃 본체는 GB10에 두고, 단계별 작업 집합만 3090에 둔다.

## A. 409,600 단일 요청

- `--max-model-len 409600`, `--max-num-seqs 1`, `--kv-mib 14336`.
- KV는 `427,468 tokens, 1.04x`를 허용하므로 정확히 완전한 요청 하나가 들어간다.
- 디코딩 중앙값: code 185.89, prose 67.28.
- 3090은 KV 14 GiB와 드래프트, 핫 캐시를 담는다. GB10은 본체와 PLE를 담는다.

## B. 340,000 두 요청

- `--max-model-len 340000`, `--max-num-seqs 2`. 디코딩 중앙값은 `--kv-mib 15360`, 장문
  프로브는 `--kv-mib 14336`에서 측정했다.
- KV는 15 GiB에서 `677,901 tokens, 1.99x`, 14 GiB에서 `631,728 tokens, 1.86x`를 허용한다.
- KV 15 GiB에서 측정한 C=2 디코딩 중앙값: code 요청당 86.79(합계 163.46), prose 요청당
  40.16(합계 78.35).
- 완전한 340,000 요청 두 개는 들어가지 않는다. 요청당 339,967 입력 토큰으로 보낸 두
  스트림 프로브가 `HTTP 400`으로 거절됐다.

## 그림이 주장하지 않는 것

장문 프로브는 315,000토큰 요청 두 개를 완료했지만 비스트리밍이었고 총 소요 시간만
기록했다. TTFT 겹침, 스케줄러 KV 점유, preemption을 기록하지 않았으므로, 그림은 설정된
슬롯을 보여줄 뿐 동시 상주를 증명하지 않는다.

짧은 프롬프트 동시성은 별도로 측정됐다. C=2 합계 code 260.81, prose 86.60이고, C=4 합계
code 302.98, prose 115.28이며 모두 `streamsFailed == 0`이다.
